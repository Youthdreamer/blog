## 特性

- **零依赖**：构建与预览只用 Node 内置模块，无任何第三方包；pnpm 仅作脚本入口，无需 `pnpm install`
- **手写 Markdown 解析器**：标题、粗体/斜体/删除线、行内代码、内/外链接、图片（含图注）、引用、列表、表格（GFM 管道语法，支持对齐）、分隔线、围栏代码块（围栏信息带行号表 `{3,5-7}` 可标行）、评分卡（`score` 围栏，列表卡片上带评分徽标）、折叠块（`fold` 围栏，点开揭晓）、提示框（`note` 围栏，旁批便笺）、键帽（`[[Ctrl+w]]`）
- **新文章向导**：`pnpm run new` 一问一答填写全部字段，自动生成文章、打开预览、可选拉起编辑器
- **阅读体验**：长文自动目录（TOC）、阅读进度条、上一篇/下一篇、相关文章推荐（按共同标签）、隐藏式落款（微尘浮沉）
- **代码高亮 + 复制按钮**：highlight.js 本地自托管；围栏信息里写行号表（`{3,5-7}`）可标行
- **图片**：懒加载 + 点击放大（零依赖 lightbox）+ 香槟金细边
- **链接悬停预览**：站内文章/页面富预览 + 外站 favicon/域名预览
- **首页特效**：鼠标光晕、点击墨滴涟漪、逐字浮现标题、漂浮墨尘
- **分页 / 置顶**：文章过多自动分页；`pin: true` 置顶到列表最前
- **标签页**：加权词云（字号平滑缩放、错峰浮动、悬停金线）+ 标签归档页
- **合集页**：frontmatter 写 `series: 合集名`，或把文章直接放进 `content/posts/合集名/` 文件夹（文件夹即合集，优先于 `series:`）——不同时间发布的文章，按顺序连成一条完整的教程线；卡片式索引页 + 合集内序号，`series_order` 可手动定位；文章页底部附合集上/下篇，顺着依次读
- **回到顶部**：菱形按钮，滚动浮现、平滑回顶
- **自定义 404**：自包含渲染，任意深度 URL 都正常显示
- **年份自动获取**：页脚 © 与 est. 构建时自动取当年
- **SEO**：canonical、Open Graph、Twitter Card、JSON-LD、`sitemap.xml`、`robots.txt`、RSS
- **响应式与无障碍**：窄屏适配、`prefers-reduced-motion`、焦点环
- **GitHub Pages 自动部署**：每次 push 自动构建发布

## 快速开始

```bash
pnpm run new      # 新文章向导（写作入口，推荐）
pnpm run dev      # 开发模式：改 content/ 或 assets/ 自动重建 + 浏览器刷新
pnpm run build    # 一次性构建站点 → site/
pnpm run serve    # 静态预览（默认 8000，PORT=9000 换端口）
pnpm run stop     # 停止开发服务器（按 .dev.pid 定位）
pnpm run fields   # frontmatter 字段参考
```

> 全部命令等价于 `node <脚本>.js`；pnpm 只是脚本入口，无需 `install`。

打开 http://127.0.0.1:8000 即可。

## 写一篇文章

### 方式一：向导（推荐）

`pnpm run new`——一问一答填写全部字段，生成文章并打开预览：

```
$ node new.js

  ◇ youth · 新文章向导
  ────────────────────────────

01/13 标题：NixOS 折腾记
02/13 文件名 [nixos-折腾记]：nixos-guide
  → nixos-guide.md · URL：/post/nixos-guide.html
03/13 日期 [2026-08-18]：
04/13 更新日期（可空，留空不显示"更新于"）：
05/13 标签（空格分隔，可空）：NixOS 配置
06/13 合集（可空）：NixOS 入门
07/13 合集序号（第几篇，可空=按日期）：2
08/13 摘要（一句话，可空）：把系统写进一个文件
09/13 阅读时长（分钟，可空=自动估算）：
10/13 草稿？（y/N）：n
11/13 置顶？（y/N）：n
12/13 隐藏目录？（y/N）：n
13/13 隐藏卡片评分？（y/N）：n

  确认信息 ────────────────────────
  № 01  标题       NixOS 折腾记
  № 02  文件名     nixos-guide
  № 03  日期       2026-08-18
  № 04  更新日期   （空）
  № 05  标签       NixOS, 配置
  № 06  合集       NixOS 入门
  № 07  合集序号   2
  № 08  摘要       把系统写进一个文件
  № 09  阅读时长   自动
  № 10  草稿       否
  № 11  置顶       否
  № 12  隐藏目录   否
  № 13  隐藏卡片评分 否
  ────────────────────────────
  → content/posts/nixos-guide.md · URL：/post/nixos-guide.html
回车确认生成，或输入编号修改 [确认]：   ← 输入编号可返回修改任意一项

  ✓ 已创建 content/posts/nixos-guide.md
  → http://127.0.0.1:8000/post/nixos-guide.html
```

向导的贴心之处：

- 文件名输入后**立即检查冲突**（根下或任何合集文件夹里的同名文件 / 其他文章 frontmatter 占用），绝不覆盖
- 合集名与 `content/posts/` 下已有的文件夹同名时，文章直接写进那个文件夹（文件夹即合集，frontmatter 不再写 `series:`）；确认页上能看到最终落点
- 确认页输入编号可返回修改任意一项
- 询问后可用 `$VISUAL`/`$EDITOR` 打开新文件直接写作（默认不打开；终端编辑器如 nvim 会在独立终端窗口打开）
- dev 服务器在向导终端**前台运行**：日志持续可见，`Ctrl+C` 停止（编辑器窗口独立不受影响）
- 全部字段参考：`pnpm run fields`

### 方式二：手动创建

在 `content/posts/` 新建 `.md`。frontmatter 字段一览：

| 字段 | 必填 | 作用 |
| --- | --- | --- |
| `title` | ✅ | 文章标题 |
| `date` | ✅ | 发布日期（`YYYY-MM-DD`） |
| `slug` | ⚠️ | 文件名 / URL（缺省取文件名，含中文时建议显式指定） |
| `updated` | | 最后更新日期，文章页显示"更新于"，写入 JSON-LD |
| `tags` | | 标签数组，如 `[NixOS, 配置]` |
| `series` | | 合集名，同一部教程系列的文章填同一个名字（把文章放进 `content/posts/合集名/` 文件夹也行、此时不用写；两者都有时文件夹优先） |
| `series_order` | | 第几篇（正整数），固定本文在合集中的位次；缺省按发布日期升序 |
| `summary` | | 一句话摘要，显示在文章列表 |
| `minutes` | | 手动阅读时长（缺省按字数自动估算） |
| `draft` | | `true` = 草稿，不发布 |
| `pin` | | `true` = 置顶到列表最前 |
| `toc` | | `false` = 隐藏本文目录 |
| `score_badge` | | `false` = 列表卡片上不显示评分徽标 |

```markdown
---
title: 文章标题
date: 2025-08-20
slug: my-post
---
```

### 合集：放进文件夹也行

把文章直接放进 `content/posts/<合集名>/` 文件夹，它自动归入那部合集，连 `series:` 都不用写——文件夹就是合集，像 Next.js 的文件路由：

```text
content/posts/
├── Neovim教程/
│   ├── neovim-guide.md        ← 自动属于「Neovim教程」
│   └── nvim-plugin-share.md
├── 个人影评/
│   └── interstellar.md
└── first-letter.md            ← 根下的文章照旧靠 frontmatter 的 series:
```

四条规矩：

- **只认一层文件夹**：`个人影评/2026/x.md` 这种两层的不算，构建时会提醒并跳过（不静默丢文章）
- **文件夹名 = 合集名**：与 `series.md` 的简介、`series_order` 的用法全都照旧；名字首尾别带看不见的空白（构建会提醒）
- **文件夹优先**：文件夹里又写了不一样的 `series:`，以文件夹为准（提醒一句）；写了同名则两不相扰——搬家路上不必急着删那行
- **`_` 或 `.` 开头的文件夹是私用空间**：整块跳过（草稿、素材放这儿）；`_` 开头的**文件**不受影响，照旧发布

文章 URL 仍是扁平的 `/post/<slug>.html`，合集页也仍在 `/series/<合集名>.html`——文件夹只决定归属，不改地址，旧链接不会坏。夹内顺序也照旧：按日期，`series_order` 可手动定位。

### 合集简介（可选）

合集索引页上每张卡片的简介，独立写在 `content/series.md` 里，一行一部合集：

```text
Neovim 入门: 从装好到写起来：插件、配置、LSP，按顺序读下来就够用。
```

冒号（半角 `:` 或全角 `：`）前的名字要与合集名完全一致（就是文件夹名或 frontmatter 的 `series`，两者精确匹配）；空行和 `#` 开头的行忽略，简介里可以再用冒号。没在这里写简介的合集，卡片上就不显示。

### Markdown 语法

支持：**粗体**、*斜体*、~~删除线~~、`` `行内代码` ``、[链接](https://example.com)、引用、列表、标题、分隔线、图片（含图注）、围栏代码块、**表格**。行内语法可嵌套，如 `**粗体 *斜体* 粗体**`、`**粗体** 里嵌行内代码或链接`。

站内文章链接直接写文件名——构建时自动换成文章 URL，悬停有富预览：

```markdown
[另一篇](./another-post.md)   ← 也支持 `./合集文件夹/某篇.md`、带 #锚点
```

目标按文件名找（frontmatter 的 `slug` 覆盖了文件名时按 slug 找）；找不到、指向草稿、或对上了多篇同名文章时，链接原样保留，构建日志里提醒一句。

表格使用 GFM 管道语法（前后需留空行，支持对齐）：

```markdown
| 名称 | 数量 |
| :--- | ---: |
| 甲   | 2    |
```

对齐方式：`:---` 左对齐 · `:---:` 居中 · `---:` 右对齐。

构建：`pnpm run build`。文章按日期倒序排列（`pin: true` 置顶最前），`draft: true` 自动隐藏；slug 重复时构建会**报错并列出冲突文件**。

### 评分卡

影评、游戏评价可以用一段 `score` 围栏生成一张十分制评分卡（每颗菱形格是 1 分）：

````markdown
```score
9.5                ← 只写一个数：总分（写成 9.5/10 也行，不写满分就按十分制）
评语: 值得一看      ← 一句话评语，落在分数下面
剧情: 10           ← 「名字: 分数」各画一排刻度
表演: 在线          ← 分项不是数字，就照原样写在右边
```
````

分项可以不写；一行内容都没有时整块跳过。数据有问题（评分不是数字、评了 12/10 之类）只在构建日志里提醒，不会挡住构建。

文章正文里有评分卡，列表卡片（首页 / 标签页 / 合集页）就会跟着挂一枚 `◇ 9.8/10` 的徽标——只认**第一张**评分卡的总分；没写总分的卡不挂，只画分项。不想挂某篇的徽标，就在它的 frontmatter 里写 `score_badge: false`（只收徽标，正文里的评分卡照常显示）。

### 折叠块（点开揭晓）

影评要聊结局、教程想把答案先盖住——用一段 `fold` 围栏生成一个默认合着的折叠块，读者自己决定要不要点开：

````markdown
```fold
剧透警告：下面要讲结局了   ← 第一行 = 露在外面的提示语，空着就是「此段封存」
结局其实是……              ← 其余都是折起来的正文，照常写 markdown
```
````

几条说明：

- 合着时像一封压了印的信（金边 + 淡斜纹 + ◆），点开后封条褪去、◆ 转 ◇、「点开揭晓」换成「收起」；开合是一段平滑过渡，禁用 JS 或系统开了「减少动效」时就是干脆的开合，功能不受影响
- 正文照常写 markdown，但**里面的标题不进目录、评分卡不挂列表徽标**——合着的内容不在外面留痕
- 正文里要放代码块**或别的围栏**就用**四个反引号**开栅（在 `fold` 前面多写一个反引号即可），三反引号留给里面的内容（上面这个示例块自己就是这么写的）；忘了加长时构建日志会提醒一句——同长的围栏分不清「嵌进来」还是「关上」，只会把外层提前关掉
- 正文一行内容都没有（或只有提示语）时构建提醒一句并跳过；合着的折叠打印时不会自动展开（浏览器的规矩）

### 提示框（旁批便笺）

教程里「注意 / 坑 / 别踩」这类话，用一段 `note` 围栏生成一张旁批便笺——淡金晕底、发丝描边，左缘一枚 ◆ 对着第一行，像写在书页边上的批注：

````markdown
```note
改配置前先**备份**：`~/.config/hypr/hyprland.conf` 改坏了容易进不去桌面。
```
````

几条说明：

- 整段都是正文，照常写 markdown（段落、列表、粗体、链接都行）；纸白正体，不斜体——斜体是引用块的腔调，提醒是作者自己的声音
- 与折叠块同一规矩：**里面的标题不进目录、评分卡不挂列表徽标**；要嵌代码块或别的围栏同样用**四个反引号**开栅
- 一行内容都没有时构建提醒一句并跳过

### 代码行高亮

教程里想标「就改这一行」，在围栏信息里带上行号表即可：

````markdown
```js {3,5-7}
```

几条说明：

- `N` 单行、`N-M` 区间，逗号分隔，留白随意（`{ 3 , 5-7 }` 也认）
- 排序后**相连的也会合并**（`{5,3-4,4}` → `3-5`）——色带是半透明的，相叠会出一道深印
- 倒着写（`{7-5}`）按正序算，`0` 收成 1；单行超出实际行数整条丢弃、区间收边到末行——整段解析不出行号时构建日志提醒一句（块照常渲染）
- 标亮的样子：淡金色带 + 一条 2px 左金条；长行横向滚动时色带跟着字走
- 行号表只认纯代码围栏：`score` / `fold` / `note` 跟着的花括号一律不管

### 键帽

Neovim 教程通篇快捷键，把按键写成 `[[Ctrl+w]]`，就渲染成一枚按得下去的键帽：

```markdown
按 [[Ctrl+w]] 切窗口，按 [[q]] 退出
```

- 整串就是一个键帽（字面就是键帽上印的字样），不拆 `+`
- 想写字面的 `[[x]]`，用行内代码包住即可：`` `[[x]]` ``

## Nix 开发环境（NixOS）

项目带 `flake.nix`（`.envrc` 已配 `use flake`），进入目录自动加载开发环境：

- **工具**：Node 24、pnpm（脚本入口）、git、ImageMagick（图片处理）
- **进入方式**：`nix develop`（或装 `direnv` 后进入目录自动激活）
- **可复现构建**：`nix build` 输出纯静态站点到 `result/`
- **一键起 dev**：`nix run .#dev`
- 修改 `flake.nix` 后：`nix flake update` 或 `nix develop --refresh` 生效

| 配色 | `assets/css/base.css` 的 `:root` 变量 |
| 字体 | `lib/shell.js` 的 `FONTS` + `base.css` 字体变量 |
| 导航 / 页脚文字 | `lib/shell.js` 的 `nav()` / `footer()` |
| 相关文章推荐篇数 | `lib/views.js` 的 `relatedPosts()`（`n` 参数） |
| 回到顶部按钮 | `assets/css/components.css` 的 `#to-top` |
| 彩蛋台词 | `assets/js/core.js` 的 `showToast(...)` |
| 关于页内容 | `content/pages/about.md` |

> 配色是"高级感"的关键：金色只用在链接、标记、印章这类**需要被看见**的地方，正文保持纸白色。

## 部署到 GitHub Pages

1. 推到 GitHub 仓库（`git push -u origin main`）
2. 仓库 `Settings → Pages → Build and deployment` 的 **Source 选 `GitHub Actions`**
3. 每次 push 自动构建并发布（见 `.github/workflows/deploy.yml`）
4. 把 `lib/config.js` 里的 `SITE.url` 改成你的真实地址——**canonical / sitemap / og:url / RSS 都依赖它**
5. 构建自动生成 `sitemap.xml`、`robots.txt`、`feed.xml`，每页写入 JSON-LD

> 站点用全相对路径，部署在 `用户名.github.io/仓库名/` 子路径下也能正常显示。当前 `SITE.url` 预填 `https://Youthdreamer.github.io/blog`，部署前请核对。
